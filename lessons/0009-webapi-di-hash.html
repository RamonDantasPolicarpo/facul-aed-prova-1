💉 Injeção de Dependência (DI)

Em vez de o Controller dar new AppDbContext() dentro de cada método (o que cria acoplamento forte e risco de esquecer de fechar a conexão), você registra o serviço no Program.cs:

builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlite(builder.Configuration.GetConnectionString("DefaultConnection")));

O container de DI do ASP.NET Core cria o AppDbContext, injeta no construtor do Controller (igual @Autowired no Spring) e descarta automaticamente ao final da requisição HTTP (ciclo Scoped).

🔐 Criptografia vs Hash (MD5, SHA-256 e Senhas)

ConceitoDireçãoObjetivo principalExemplos
CriptografiaMão dupla (reversível com chave)ConfidencialidadeAES, RSA
HashMão única (irreversível)Integridade e assinatura digitalMD5, SHA-256
⚡ MD5 vs SHA-256 vs Senhas:
  • MD5 (128 bits): Obsoleto e inseguro — sofre de vulnerabilidade a colisões (dois arquivos diferentes gerando o mesmo hash).
  • SHA-256 (256 bits): Seguro para verificar integridade de arquivos e assinaturas digitais (efeito avalanche: 1 bit mudado altera todo o hash).
  • Senhas: Nunca use MD5 nem SHA-256 puro (são rápidos demais para força bruta). Use bcrypt ou Argon2id, que possuem salt e work factor configurável.

🧪 Teste rápido

1. Qual código HTTP uma API REST deve retornar ao criar um novo produto via POST?

  • 201 Created com CreatedAtAction
  • 200 OK com corpo vazio
  • 204 No Content sem corpo
  • 400 Bad Request de entrada
✅ Isso! POST que cria um recurso retorna 201 Created (no ASP.NET Core, via CreatedAtAction).
❌ Atenção: 200 é para GET, 204 para PUT/DELETE sem corpo. Criação com POST retorna 201 Created.

2. Por que o algoritmo MD5 não deve ser usado para segurança crítica?

  • Sofre vulnerabilidade prática a colisões
  • Permite descriptografia reversa com chave
  • Exige processamento lento em servidor
  • Gera saídas de tamanhos variáveis
✅ Exato! O MD5 (128 bits) permite que arquivos diferentes gerem o mesmo hash (colisão).
❌ Lembre-se: todo hash é mão única e de tamanho fixo; o problema do MD5 é a vulnerabilidade a colisões.

3. Qual a principal vantagem de registrar o DbContext no container de DI em vez de usar new?

  • Desacoplamento e descarte automático Scoped
  • Execução direta sem usar banco
  • Compartilhamento global em modo Singleton
  • Conversão automática de JSON inválido
✅ Perfeito! O container de DI desacopla a criação e gerencia o ciclo de vida Scoped (1 por requisição HTTP).
❌ Não! O container serve para desacoplar e gerenciar o ciclo de vida (Scoped) e o descarte automático ao fim da requisição.
